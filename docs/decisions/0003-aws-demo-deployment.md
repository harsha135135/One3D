# 0003: The on-demand AWS demo

Date: 2026-10-12 (Checkpoint 7). Status: accepted. The owner approved the setup, the costs and the identity plan on 2026-10-12; the owner review of the code is deferred.

## Context

The demo has to stay within the AWS promotional credits shared with OneCreations, which runs in the same account. The owner set these constraints:
- One3D's allocation is US$55. OneCreations has $25, and there is a $20 shared reserve. Nothing may be paid out of pocket.
- One3D runs on demand and is stopped otherwise.
- OneCreations must stay unchanged.
- A dedicated deployment identity is used, not root.
- No load balancer, NAT gateway or managed services that are not needed.

**Credits on 2026-10-12:**
- The Free Tier API reported a paid plan with $119.47 remaining.
- The Credits page showed "AWS Free Tier" ($100, expires 2027-10-01) and "Explore AWS: set up a cost budget" ($20, expires 2027-09-30).
- The applicable products of each line are not shown there, so the out-of-pocket budget below is the safeguard.

## Decision

**Compute and network:**
- One `t3.small` (x86, 2 GiB) in the default VPC of `ap-south-1`, with an Elastic IP and a security group open only on 80 and 443. There is no SSH; SSM handles commands and sessions.
- CPU credits are "standard", so the instance is never billed for surplus CPU.
- Termination protection is on.
- A changed first-boot script never replaces the instance.

**Containers:**
- Nginx (TLS from Let's Encrypt), the frontend, the backend, PostgreSQL and the simulator, under Docker Compose.
- Only Nginx is published.
- Memory limits come from local measurement (Checkpoint 7 evidence).

**Data:**
- PostgreSQL, the simulator journal and the certificates are on a separate encrypted 4 GB gp3 volume. It survives stop/start and instance replacement, and Docker starts only once it is mounted.
- Model files are in a private, versioned, encrypted S3 bucket.
- Database backups (`demo.sh stop`) go to a second private bucket.

**Managed services, and only these:**

| Service | Why |
|---|---|
| Cognito (Lite tier) | OIDC sign-in with required TOTP MFA |
| ECR | Images; tags are immutable |
| SSM Parameter Store | Configuration and secrets |
| S3 | Files, backups and deploy bundles |
| AWS Budgets | Credit and out-of-pocket alerts |

**Identities:**
- Root was used once, to create the IAM user `one3d-deployer`. That user has console access with MFA and no access keys, and is used with `aws login`.
- Its policy allows One3D-named resources in `ap-south-1` and explicitly denies each OneCreations resource. The AWS-managed `SignInLocalDevelopmentAccess` policy lets the user use `aws login`.
- GitHub Actions uses an OIDC role that only `main` can assume.

**Deployment:**
- CI builds the images on every run.
- On `main`, after all tests pass, CI pushes the images by commit SHA and deploys through SSM.
- A push while the demo is stopped is skipped, and `demo.sh start` deploys the latest passing commit.

**Budgets (account-wide, free):**
- `Account-Credit-Use`: monthly usage before credits, limit $15. Alerts at 50%, 80% and 100% actual and 100% forecast.
- `Account-Out-Of-Pocket`: cost after credits, limit $1. Alerts on any charge.
- The existing OneCreations budget is unchanged.

## Rejected alternatives

| Alternative | Saving | Why not |
|---|---|---|
| `t4g.small` (ARM, $0.0112/h) | about $3–5 over the period | ARM images built under emulation on GitHub's x86 runners. Possible later |
| Route 53 with dynamic DNS instead of the Elastic IP | about $20 | While stopped, the record would point at a released address that another AWS customer could get, and they could then pass Let's Encrypt validation for the domain. It also needs NS delegation at Hostinger |
| Larger instances, a load balancer or RDS | — | Unnecessary for one demo |

## Consequences

- **Standing cost:** while stopped, the demo still costs the Elastic IP and the disks, about $0.18 a day. Only destroying it ends that (`infra/README.md`).
- **Data in Terraform state:** the database password and the Cognito client secret are generated by Terraform, so they are in its state, which is in a private, encrypted, versioned bucket. Razorpay's keys are not in the state.
- **Cognito MFA covers everyone:** the setting is per pool, so demo customers need an authenticator app too.
- **The simulator's `/dev` controls are on in the deployed demo.** A print finishes only when someone says so, because there is no printer. They are reachable only on the internal Docker network, through SSM.
